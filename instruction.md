# Prompt для разработки микросервиса FastAPI

## Контекст проекта
Я строю систему автоматизации поиска и анализа контента для YouTube-каналов. 
- **Цель:** Избежать лимитов YouTube Data API и дорогого браузерного парсинга.
- **Текущая архитектура:** n8n собирает первичный список каналов -> отправляет их на мой Python-сервер (FastAPI) -> сервер анализирует контент и возвращает результат.

## Требования к реализации FastAPI
Необходимо создать асинхронный сервер (FastAPI), который будет выполнять роль "Worker-а" для транскрибирования и анализа видео.

### Основной функционал:
1.  **Endpoint `/process_channel`:**
    *   Принимает `channel_url` (или `channel_id`).
    *   Использует `yt-dlp` для извлечения последних 5-10 Shorts (фильтрация по длительности `< 60 сек`).
    *   Использует `youtube-transcript-api` для получения транскрипции каждого Shorts.
2.  **Анализ контента:**
    *   Каждая транскрипция должна отправляться в LLM (OpenRouter/OpenAI API).
    *   **Промпт для LLM:** "Ты аналитик контента. Проанализируй эту транскрипцию. Оцени её соответствие тематике 'IT-аутсорсинг' по шкале от 1 до 10. Верни JSON: `{'score': int, 'reason': str, 'should_rewrite': bool}`."
3.  **Обработка ошибок:**
    *   Если транскрипция недоступна (например, авто-субтитры отключены или видео без слов), сервис должен корректно пропускать это видео и логировать ошибку, не падая.

### Технические требования:
- Использовать `pydantic` для описания моделей данных (Request/Response).
- Использовать `async/await` для всех сетевых операций (IO-bound задачи).
- Код должен быть модульным: отдельно логика получения ссылок, отдельно транскрипция, отдельно взаимодействие с LLM.
- **Безопасность:** Реализуй минимальный API-key заголовок (`X-API-KEY`) для защиты эндпоинта от публичного доступа.

## Ожидаемый результат
1. Структура проекта (файлы `main.py`, `services/`, `models/`).
